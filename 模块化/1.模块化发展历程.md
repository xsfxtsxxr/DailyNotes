### 1.IIFE： 使用匿名自执行函数来编写模块化，特点：在一个单独的函数作用域中执行代码，避免变量冲突。

```js
;(function () {
  var a = 1
  console.log(a)
})()
```

### AMD： 使用 requireJS 来编写模块化，特点：依赖必须提前声明好。模块加载异步，指定回调函数(使用在浏览器端)

```js
// 定义模块(无依赖)
define(function () {
  // return 模块
})

// 定义模块(有依赖)
define(['./index.js', './main.js'], function (index, main) {
  // index 就是index.js 返回的内容
  // main main.js 返回的内容
  return [index, main]
})

// 使用模块
require(['index', 'main'], function (index, main) {
  // 使用index、main
})
```

### CMD： 使用 seaJS 来编写模块化，特点：支持动态引入依赖文件。模块加载是异步的，模块使用时才会加载执行(使用在浏览器端)

```js
// 定义模块(无依赖)
define(function (require, exports, module) {
  // 暴露模块两种写法如下：
  // exports.xxx = value
  // module.exports = value
})

// 定义模块(有依赖)
define(function (require, exports, module) {
  // 引入依赖模块(同步)
  var module2 = require('./module2')
  // 引入依赖模块(异步)
  require.async('./module3', function (module3) {
    // 使用依赖模块
  })
  // 暴露模块
  // exports.xxx = value
})

//使用模块(同步)
var fs = require('fs')
// 使用模块(异步)
require.async('./module3', function (m3) {
  // 使用模块
})
```

### CommonJS：(服务器端 Node.js、浏览器端 webpack 和 browerfy)

#### 模块加载同步，即资源加载完成再执行，每个文件都可以是一个模块

#### 服务端模块加载是运行时同步加载，浏览器模块加载是提前编译打包处理

```js
// 使用第三方模块
var fs = require('fs')
//使用自定义模块
require('./xxx.jpg')
// 使用模块，读入并执行一个javascript文件，然后返回改对象的exports对象，如果没有发现指定模块会报错。

// 定义模块
// exports.xxx = value
// module.exports = value
// module变量代表当前模块。这个变量是一个对象，它的exports属性(即module.exports)是对外的接口。
```

### ES Modules： ES6 引入的模块化，支持 import 来引入另一个 js。(服务器端和浏览器端通用)

#### 与 commonJS 区别：

```
输出值：
ES Module是动态引用，并且不会缓存值，输出的是一个对外的接口，一个值的引用
CommonJS可以多次引入，但是只会在第一次引入时候加载一次，然后运行结果就被缓存了，以后再加载就直接读取缓存结果，要想让模块再次运行必须清除缓存。

加载方式：
CommonJS加载的是一个对象(即module.exports属性),该对象只有在脚本运行完成才会生成，因此它是运行时加载。
ES Module加载的是一个接口，该接口只是一个静态定义，在代码静态解析阶段就会生成，因此它是编译时输出接口。
```

```js
// 引入
import a from 'a'

// 暴露
// export default 模块 或者 export 模块
```
